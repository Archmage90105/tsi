# tsi 0.7.0: расхождения с ТЗ, модель доверия, чек-лист пробного запуска

Установщик Tailscale для OpenWrt 24.10 (opkg) и 25.12+ (apk). Один файл `tsi.sh`
(8 слоёв), 7 наборов тестов (1073 проверки на моках). Документ описывает, что
в реализации отличается от согласованного ТЗ, на чём держится доверие к
скрипту и что ещё нужно проверить на железе.

## 1. Что где лежит

| Что | Путь |
|---|---|
| Скрипт и алиас | `/usr/bin/tsi` (копия файла, не симлинк) |
| Конфиг скрипта | `/etc/tailscale-installer.conf` (ключи: `LANG`, `INSTALL_SOURCE`, `B_SUBMODE`, `LOGIN_SERVER`, `NETFILTER_MODE`, `LITE_VERSION`, `LOG_VERBOSE`) |
| Учёт добавленных фидов | `/etc/tailscale-installer.feeds` (строки `имя\|url\|id ключа`) |
| Лог, стек отката, бэкап конфигов | `/tmp/tsi/` (каталог 700, пропадает при перезагрузке) |
| Секции uci | `network.tsi_net`, `network.tsi_route`, `firewall.tsi_zone`, `tsi_fwd_lan_in`, `tsi_fwd_lan_out`, `tsi_fwd_wan` |

Запуск: `wget -O /tmp/tsi.sh <URL> && sh /tmp/tsi.sh` (в начале слоя 4 константа
`TSI_URL`, пока плейсхолдер `__PLACEHOLDER__`).

## 2. Расхождения с ТЗ

**п.2 Язык.** Выбор языка спрашивается только в режиме меню. В неинтерактивных
режимах и в `--status` вопроса нет, язык по умолчанию русский, в конфиг ничего
не пишется.

**п.3 Определение системы.** Пакетный менеджер определяется по наличию `opkg`
или `apk`, версия из `/etc/openwrt_release` служит только для сверки.
`TS_ARCH` (Go-архитектура) нужна лишь для проверки ELF скачанного бинарника;
пути фида строятся из архитектуры пакетного менеджера (`opkg print-architecture`
или `/etc/apk/arch`), запасной вариант `DISTRIB_ARCH` с предупреждением.

**п.4 DNS-пакеты.** Решение по netfilter принимается до установки пакета.
`dnsmasq-full` считается конфликтным, только если в `uci dhcp` есть `nftset` или
`ipset`. Неинтерактивно при найденных конфликтах без `--netfilter-off` скрипт
останавливается с ошибкой. Значение, уже заданное в конфиге, молча не меняется.

**п.5 TUN.** Проверка идёт через `ip tuntap add`; если `ip` без `tuntap`
(`ip-tiny`), но устройство `/dev/net/tun` есть, режим считается доступным с
предупреждением. `--tun=userspace-networking` не реализован (в init-скрипте
пакета такой опции нет). Без TUN: неинтерактивно установка прерывается,
интерактивно задаётся вопрос.

**п.6 Источники установки.**
- Lite через фид (подписанный, GitHub Pages): `opkg`, ключ `key-build.pub`;
  `apk`, ключ `key-build.rsa.pub`. Архитектурная директория фида общая для обоих
  менеджеров.
- Direct (ветка `feed`, raw): только opkg на 24.10. Версия из файла `version`
  (формат `1.104.1-r1`), хэш из `ipk.sha256` (имя фиксированное, лежит в каталоге
  архитектуры), пакет ставится через менеджер (`opkg install файл.ipk`), поэтому
  работают hold, remove, `pkg_version`. Подпись пакета не проверяется: подтверждение
  вводом слова `yes`. Хэши `LITE_SHA256_*` из конфига удалены.
- `--allow-untrusted` не используется нигде.

**п.7 LuCI.** Отдельный шаг (после инструкций по установке и пункт меню настроек).
25.12+: пакет `luci-app-tailscale-community` из официального фида. 24.10: фид
Tokisaki-Galaxy (`…/all`; для apk ключ называется `public-key.pem`). Фид GuNanOvO
LuCI-приложения не содержит. Нужен установленный `luci-base` (иначе шаг
пропускается). В неинтерактивном режиме не устанавливается.

**п.8 Firewall.** Автонастройки в пакетах нет. Настройка через uci в секциях
`tsi_*`: интерфейс `tsi_net` (`proto none`, `device tailscale0`), зона с
`name tailscale` (ACCEPT/ACCEPT/ACCEPT, masq, mtu_fix), forwarding tailscale↔lan.
Forwarding tailscale→wan создаётся отдельно (пункт меню), он нужен для exit node.
Чужие зону и интерфейс скрипт ищет по содержимому и при их наличии ничего не
создаёт. Перед изменениями проверяется `uci changes`. Применение через `reload`.
Режим firewall для tailscaled: `tailscale.settings.fw_mode` (`nftables`, если есть
`fw4`, иначе `iptables`).

**п.9 Сервер.** Адрес вводится без схемы, `https://` подставляется скриптом,
`http://` и другие схемы отвергаются.

**п.10 `tailscale up`.** Команда собирается из полного набора текущих значений
(`--login-server`, `--netfilter-mode=off`, `--advertise-exit-node`,
`--advertise-routes`), без `eval`. Запускается не через `run_ext`: вывод идёт на
экран по мере появления (ссылка авторизации), копия уходит в лог. Список подсетей
проверяется строго (только IPv4, без `/0`, без ведущих нулей, без битов хоста).
`route_check_cgnat` вызывается после успешного `up` и только на 24.10.

**п.11 Служба.** `enable`, `start`, ожидание до 5 секунд; init-скрипт и
`/etc/config/tailscale` лежат внутри пакета, собственный procd-скрипт не создаётся.

**п.12 sysupgrade.** В `/etc/sysupgrade.conf` добавляются `/usr/bin/tsi`,
`/etc/tailscale-installer.conf`, `/etc/tailscale-installer.feeds`,
`/etc/config/tailscale`, `/etc/tailscale/`, `/var/lib/tailscale/`, а также файл
фидов и ключи фидов из учёта.

**п.13 Обновление.** Фид: `unhold` → `update` → `upgrade` → `hold`, hold
возвращается при любом исходе. Direct: сначала читается версия, `yes` запрашивается
только при наличии новой, затем `unhold` → установка файла → `hold`. Официальный
пакет: `update` → `upgrade`. Служба перезапускается, только если версия изменилась.

**п.14 Удаление.** Порядок: подтверждение (`yes`), служба, firewall, LuCI-пакет,
фиды `luci` и `lite`, пакет tailscale (с `unhold`), остатки (`/etc/config/tailscale`,
`/etc/tailscale/`, `/var/lib/tailscale/`: пакет их не удаляет), конфигурация скрипта
(по запросу), алиас и записи sysupgrade, итоговый отчёт. Если сам пакет удалить не
удалось, остаются состояние, алиас и записи sysupgrade. Зависимости (`kmod-tun`,
`ca-bundle` и др.) не удаляются.

**п.16 Меню.** Главное: установить, обновить, удалить, статус, настройки, выход.
Настройки: язык, сервер, режим netfilter, forwarding в wan, режим firewall,
подробный лог, просмотр конфигурации, LuCI, exit node/подсети/`tailscale up`.

**п.17 Алиас и запуск.** `/usr/bin/tsi` это копия файла. Запуск через пайп
(`wget … | sh`) явно отвергается с подсказкой двухшагового запуска.

**п.18 Откат и целостность.** Автоматически откатываются секции `tsi_*` и добавленный
фид (через стек в `/tmp/tsi/`); пакеты и зависимости остаются до явного удаления.
Целостность: для фида подпись индекса проверяет менеджер, для direct хэш
`ipk.sha256` (защита от битой загрузки, не от компрометации источника).

## 3. Командная строка

```
tsi                      меню
tsi --status             статус (без вопросов)
tsi --update             обновление (неинтерактивно)
tsi --install-official   установка официального пакета (неинтерактивно)
tsi --install-lite       установка Lite через подписанный фид (неинтерактивно)
     --netfilter-off     модификатор: отключить управление netfilter
     --login-server=URL  модификатор: свой сервер
tsi --help / -h, --version / -V
```

Нет флагов для удаления и direct, нет `-y` и `--quiet`. Коды возврата: 0 успех,
1 ошибка, 2 не выполнено (отказ, нужно подтверждение, неверные параметры).
Неинтерактивные режимы: вопросов нет, LuCI не ставится, `tailscale up` не
запускается (нужна авторизация), direct-обновление отвечает «только через меню».

## 4. Модель доверия: пин ключей фидов

В неинтерактивном режиме фид добавляется без вопроса только если sha256 скачанного
ключа (после удаления символов CR) совпал со значением, зафиксированным в скрипте.
Иначе отказ и вывод фактического хэша. В интерактивном режиме при несовпадении
выводится предупреждение и обычное подтверждение с отпечатком ключа.

| Ключ | Источник (raw) | sha256 |
|---|---|---|
| GuNanOvO, opkg | `…/gunanovo/openwrt-tailscale/refs/heads/feed/key-build.pub` | `f5ca65c0fa07c24bd5f6b003ccf928cd9e98f33acf8f9474d535a7c4752c1f80` |
| GuNanOvO, apk | `…/feed/key-build.rsa.pub` | `83dae13616cd902b79a84ede91417952a59d9c35e2cd216b05b3ea45eba83dd5` |
| Tokisaki, opkg | `…/Tokisaki-Galaxy/luci-app-tailscale-community/refs/heads/gh-pages/all/key-build.pub` | `eb1d2c3d17ff703dc16caee7cf6e58aee660933d96901bd68a437f3c6d3006ac` |
| Tokisaki, apk | `…/gh-pages/all/public-key.pem` | `0e2cef4d7d82101ccdcf12ae5c40b4357de86add91cc6bed95e01416c47c1017` |

Хэши посчитаны по копиям ключей в ветках репозиториев; ключи скачиваются с
`raw.githubusercontent.com` из тех же веток. Фиды и индексы по-прежнему берутся с
GitHub Pages.

Следствия:
- при смене ключа автором неинтерактивная установка откажет (fail closed), пока
  константы `LITE_KEY_SHA256_*` и `LUCI_KEY_SHA256_*` не обновлены; старые копии
  скрипта перестают работать в неинтерактивном режиме, это отражено в `--help`;
- пин защищает от подмены ключа, но не от компрометации самого автора (он
  подписывает и ключ, и пакеты);
- direct остаётся небезопасным путём (нет подписи пакета), поэтому только
  интерактивно и только с вводом `yes`.

## 5. Известные ограничения

- Режим `--tun=userspace-networking` не реализован.
- `uci commit` фиксирует весь конфиг: перед изменениями проверяется отсутствие чужих
  незакоммиченных правок, но откат (`fw_remove`) такой проверки не делает.
- IPv6-подсети в `--advertise-routes` не поддерживаются валидатором.
- При повторном запуске сценария `tailscale up` текущие флаги не подтягиваются из
  Tailscale, ответы на вопросы задаются заново.
- Сообщение «архитектура не поддерживается фидом» показывается и при недоступной
  сети (проверка индекса не различает эти случаи).
- У `riscv64_generic` нет индекса opkg, у `mips_4kec` и `riscv64_riscv64` нет
  индекса apk (по состоянию ветки `feed` на момент проверки).
- `tailscale update` на apk-системах может не работать (ТЗ п.19), скрипт его не
  использует.

## 6. Чек-лист пробного запуска

Отметки: `[x]` уже проверено в среде разработки, `[ ]` требует настоящего роутера.

### Проверено без железа

- [x] Синтаксис и тесты в dash, `bash --posix` и busybox ash 1.36 (1073 проверки).
- [x] Сквозной прогон `tsi.sh` как скрипта на моках в изолированных путях:
      `--version`, `--help`, `--status`, `--install-official`, `--update`.
- [x] Мутационные проверки ключевых правил (пин, откат, hold, порядок шагов).
- [x] Структура ветки `feed` GuNanOvO, содержимое `.ipk`, init и конфиг обоих пакетов.
- [x] Настоящие ключи GuNanOvO и Tokisaki проходят `key_validate` (usign для opkg,
      PEM для apk), перекрёстно отвергаются.
- [x] Определение архитектуры по ELF на настоящих UPX-бинарниках (x86_64, mipsel,
      mips big-endian, aarch64, arm).

### Общее для 24.10 и 25.12 (нужен роутер)

- [ ] `wget -O /tmp/tsi.sh <URL> && sh /tmp/tsi.sh --version` (разбор параметров и
      проверка root).
- [ ] `sh /tmp/tsi.sh --help` (справка на русском и английском).
- [ ] После первого запуска `/usr/bin/tsi` существует и `cmp /tmp/tsi.sh /usr/bin/tsi`
      без различий; запуск через пайп (`wget -O- URL | sh`) выводит подсказку и
      ничего не копирует.
- [ ] Первый интерактивный запуск: выбор языка, меню, установка через фид. Ввод через
      `/dev/tty` работает при запуске из SSH.
- [ ] Пин ключей: хэши скачанных ключей совпадают с таблицей из раздела 4, например
      `wget -qO- <raw-url> | tr -d '\r' | sha256sum`.
- [ ] `tailscale up` из сценария: есть ли `tee` в busybox, печатается ли ссылка
      авторизации при выводе в пайп.
- [ ] `tailscale up` на уже авторизованном узле с изменёнными флагами: ведёт ли себя
      так, как ожидает `build_up_cmd` (полный набор флагов).
- [ ] `tailscale status` и `ip route get 100.64.0.1` (маршрут через `tailscale0`).
- [ ] `uci show firewall | grep tsi_` и `uci show network | grep tsi_`: секции на
      месте; `uci changes firewall network` пусто.
- [ ] Реальный формат вывода `uci show` и `uci changes`; работа `network reload` при
      активном SSH; поднимается ли `tsi_route`, пока `tailscale0` ещё нет.
- [ ] `sysupgrade -l`: наши пути присутствуют в списке сохраняемых файлов.
- [ ] `tsi --status` до и после установки (без вопросов, коды возврата).
- [ ] Удаление через меню: остатки в `/etc/tailscale/`, `/etc/config/tailscale`
      убраны, секции `tsi_*` удалены, фиды и ключи убраны, чужое не затронуто.

### Только 24.10 (opkg)

- [ ] `opkg install файл.ipk` поверх удерживаемого (`hold`) пакета: установится ли
      без `unhold` (в скрипте всегда `unhold` → установка → `hold`).
- [ ] `opkg remove tailscale` при изменённом `/etc/config/tailscale`: что происходит
      с файлом (скрипт удаляет его сам).
- [ ] Direct-установка (пункт 3 меню): `ipk.sha256` совпадает, `opkg install файл`
      проходит, hold ставится.
- [ ] `tsi --install-lite` без терминала: пин срабатывает, фид добавляется без вопроса,
      пакет приходит именно из фида Lite (поле Maintainer: GuNan).
- [ ] Установка LuCI-приложения из фида Tokisaki: подтягивается `ip-full` вместо
      `ip-tiny`, пакет ставится.
- [ ] `route_check_cgnat`: нужен ли маршрут `100.64.0.0/10` на вашей сборке.

### Только 25.12+ (apk)

- [ ] Формат вывода `apk list -I tailscale` (на нём держится `pkg_version`).

- [ ] `tsi --install-lite` через apk-фид: ключ `key-build.rsa.pub`, пин, индекс

- [ ] Пункт 3 (direct) в меню не показывается.
